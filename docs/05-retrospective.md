## 下一步

**短周期**

1. 若仓库为私有，给指定评审账号可读权限；交卷锁定最终 SHA。
2. 为冲突类增加更硬的自动化断言（禁止回答里单独出现「15 天」或「30 天」作为定论）。
3. 交卷后若改了提示词或规则，同步更新 [04-ai-usage.md](04-ai-usage.md)，并重跑 `unittest` 与 `scripts/record_examples.py`。

**效果向**

1. 识别「废止 / 优先适用 / 适用范围」后，有明确优先级时允许 `completed`，否则继续确认。
2. 在输出中固定展示 query 改写链与选用章节，方便评审看检索改进。
3. 将 `gaps` 区分为未命中 / 命中但无关 / 读后仍不足。
4. 扩一小批回归问法：同义、错别字、跨文档组合、多轮纠错。

**工程向（后置）**

1. 可选 HTTP API 包装同一 `run()`，CLI 仍为权威入口。
2. 按部门 / 密级过滤检索可见范围。
3. 轻量引用高亮前端（非必需）。
4. 用已预留的 LangSmith 观察空检索改写率、冲突停住率与工具失败率。

**明确后置或不做：** 为热闹而堆多 Agent；无证据的「更聪明回答」；把 Mock 结果当模型能力证明。

这次没有把 fin-harness 的运行时整包搬过来。复用的是同一类约束：回答必须对应文档 ID 和原文，冲突时请求确认，工具失败不能写成查到了。
