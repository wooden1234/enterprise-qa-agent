# 需求理解

| 项目 | 定义 |
|---|---|
| 用户 | 需要查制度或产品规定的员工 |
| 目标 | 给出能回溯到原文的答案；资料不足或互相冲突时明确停下来 |
| 输入 | 当前问题，可选对话历史；可注入工具失败或步数上限 |
| 材料 | `data/documents.json` 中的合成制度，含文档 ID、标题、版本日期和正文；`data/rules.md` 规定引用和冲突处理 |
| 输出 | 回答、引用文档 ID 与原文片段、资料缺口、需要确认的问题、任务状态、执行记录 |
| 范围 | 本地 CLI。检索链路是向量、BM25、RRF，可选重排。切片在 Postgres，并保留本地切片文件 |
| 不包含 | 真实发布、权限系统、界面、线上部署 |

## 成功标准

- 只有一份资料支持时，回答与引用片段一致。
- 两份资料对同一事项给出不同事实且没有优先级时，并列引用并请求确认，不选定其中一个。
- 资料库没有依据时，说明缺口，不补写事实。
- 换一种说法提问时，可以根据空检索改写检索词。
- 追问使用对话历史，不把上一题的答案套到新问题上。
- 工具失败返回 `tool_error`，不把失败写成已经查到。
- 达到 `max_steps` 时返回 `incomplete`。

参考场景：D01《财务报销制度及报销流程》写「报销期限为 30 天」，D02《费用报销管理办法》写「报销期限为 15 天」，两处都没有适用范围和优先级。问「报销期限多久」时必须并列引用并请求确认，不能回答成 15 天或 30 天。两版《假期管理制度》对不满 10 年的年假分别写 5 个工作日和 10 个工作日，同样不能选定其中一个。只有一份资料支持、且已读原文没有冲突时，可以依据该份回答，例如 D05 的设备更换周期 36 个月。
