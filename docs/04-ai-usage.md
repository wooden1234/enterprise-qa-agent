# AI 使用说明

本项目在 Cursor 中借助 AI 辅助完成。候选人选题「企业知识问答」后，AI 参与了代码、合成资料、文档、测试与真实模型回放。密钥只从本机环境读取，没有写入仓库。框架名称本身不加分；取舍说明见 [02-solution.md](02-solution.md)。

## 分工与验证

| 阶段 | AI 做了什么 | 个人侧 / 怎么验证 |
|---|---|---|
| 选题与范围 | 按考核说明收敛到 CLI + ReAct + 合成制度，排除界面与部署 | 对照 [01-requirements.md](01-requirements.md) 成功标准 |
| 资料和规则 | 写了 D01–D05。后补 D02「报销期限为 15 天」，并在 D01 增加「报销期限为 30 天」 | 冲突用例并列两段原文 |
| 循环和工具 | 主代理与检索子代理各自按模型动作循环；检索为向量、BM25、RRF 与可选重排；子环用 LangGraph | `tests/` 与 `examples/dataset.json` |
| 真实模型 | 用 `deepseek-v4-flash` 重放明确答案、报销冲突、资料外、PTO 改写、病假追问和工具失败 | `examples/*.output.json`，`mode` 为 `live_model` |
| 修正 | 引用曾被写成字符串；提示词改为对象引用；交给主模型的发现不再重复整段正文 | 重录后冲突与改写输出第一次提交即通过审核 |
| 换文 | 临时把 D05 的 36 个月换成 24 个月，核对引用是否跟着变 | `tests/test_examples.py` 的 `ContentSwapTests` |
| 文档与交付 | 完善 README 与 `docs/`，对齐双层 ReAct 实现；推送到 GitHub | 仓库 URL 与 commit SHA 见 [05-retrospective.md](05-retrospective.md) |

## 边界说明

- 脚本模式（`scripted_mock`）的输出不能当作模型已经完成动态决策的证据。
- 能代表本次模型行为的是 `examples/` 里 `mode` 为 `live_model` 的文件。
- 不需要粘贴完整聊天记录。若之后手改了检索、提示词或检查器，在本表追加一行：改了什么、为什么改、用哪个测试或哪条输出证明。

## 个人贡献（交卷时）

- 确认题目验收点与交付目录符合考核规范。
- 审阅并要求补齐：报销期限双文档冲突、PTO 改写轨迹、六项 live 记录、换文测试、文档与仓库推送。
- 交卷说明中的思路与后续计划以仓库文档为准，可按表单字数裁剪。
